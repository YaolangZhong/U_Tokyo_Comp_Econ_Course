\begin{frame}{LLM Families and Developers}
\small
A \term{large language model (LLM)} processes context and generates text, code, or requests to perform actions.
\begin{itemize}
\setlength{\itemsep}{3mm}
\item \href{https://developers.openai.com/api/docs/models}{\textbf{GPT family}} --- developed by \textbf{OpenAI}.\\
Examples: GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna.
\item \href{https://platform.claude.com/docs/en/models/overview}{\textbf{Claude family}} --- developed by \textbf{Anthropic}.\\
Examples: Claude Fable 5, Claude Opus 5.5, Claude Sonnet 5.5.
\item \href{https://ai.google.dev/gemini-api/docs/models}{\textbf{Gemini family}} --- developed by \textbf{Google DeepMind}.\\
Examples: Gemini 4 Argon, Gemini 3.8 Flash.
\item \href{https://docs.x.ai/developers/models}{\textbf{Grok family}} --- developed by \textbf{xAI}.\\
Examples: Grok 4.20, Grok 4.7.
\item \href{https://api-docs.deepseek.com/quick_start/pricing/}{\textbf{DeepSeek family}} --- developed by \textbf{DeepSeek}.\\
Examples: DeepSeek-V4-Pro, DeepSeek-V4.1-Flash.
\end{itemize}
\end{frame}

\begin{frame}{How LLMs Are Evaluated}
\small
LLMs are commonly judged along the following dimensions.
\begin{itemize}
\setlength{\itemsep}{0mm}
\item \term{Task performance}: accuracy or success on one attempt (\textbf{pass@1}). For example, Terminal-Bench tests tasks performed with terminal tools.
\item \term{Reliability}: factual errors, instruction-following failures, and consistency across repeated runs.
\item \term{Token use and cost}: a \textbf{token} is a unit of text, often part of a word. Cost depends on token usage (including reported reasoning) and token prices; a useful measure is \textbf{cost per completed task}.
\item \term{Speed}: time to the first answer token, output tokens per second, and total completion time. Longer reasoning can increase total time.
\item \term{Input capabilities}: supported languages and \textbf{multimodal inputs}, such as text, images, audio, and video.
\item \term{Long-context performance}: context-window size and accuracy when using long documents.
\end{itemize}
\par\smallskip
\textbf{Scores depend on the test setup:} extra attempts, additional tools, or more reasoning time can improve results while increasing cost.
\end{frame}

\begin{frame}{The Harness: Tools and Interfaces}
\small
A \term{harness} is the software surrounding an LLM. It supplies tools, manages context and permissions, and returns tool results to the LLM.
\begin{itemize}
\setlength{\itemsep}{1mm}
\item \textbf{Files and coding:} search, read, create, and edit files.
\item \textbf{Execution:} run Python, terminal commands, and tests.
\item \textbf{Web access:} search the web, retrieve pages, and operate a browser.
\item \textbf{External services:} access a database, cloud drive, or other connected service.
\end{itemize}
\par\smallskip
Tools can be accessed through different interfaces:
\begin{itemize}
\setlength{\itemsep}{1mm}
\item A \term{command-line interface (CLI)} operates software through text commands. The harness can run \texttt{git status} to inspect repository changes.
\item \term{Model Context Protocol (MCP)} standardizes how applications connect to servers providing tools and information.
\end{itemize}
\end{frame}

\begin{frame}{The Agent: Coordinating a Task}
\small
\setlength{\abovecaptionskip}{0pt}
An \term{LLM-based AI agent} pursues a task by selecting actions, using tools, and adapting its next actions to the results.
\par\smallskip
{\centering\textbf{LLM + harness = AI agent}\par}
\par\smallskip
\textbf{Agent applications:}
\href{https://developers.openai.com/blog/codex-as-a-platform}{Codex} (OpenAI),
\href{https://code.claude.com/docs/en/how-claude-code-works}{Claude Code} (Anthropic),
\href{https://cursor.com/docs/agent/overview}{Cursor Agent} (Cursor),
\href{https://geminicli.com/docs/}{Gemini CLI} (Google), and
\href{https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github}{GitHub Copilot} (GitHub).

\par\smallskip
\courseexample{Example: a weekly temperature chart}\par
\textbf{You have:} a shared-drive \texttt{data.csv} with \texttt{date} and \texttt{temperature\_c}.\par
\textbf{You want:} a checked chart in date order, with Celsius units, and a reusable Python script.
\begin{figure}\centering
\begin{tikzpicture}
\node[agentNode,text width=2.65cm,minimum height=18mm,font=\scriptsize] (a) {\textbf{1. Fetch data}\\LLM requests the CSV;\\harness downloads it\\through MCP.};
\node[agentNode,text width=2.65cm,minimum height=18mm,font=\scriptsize,right=3mm of a] (b) {\textbf{2. Write script}\\LLM generates code;\\harness saves it\\with a file tool.};

\end{tikzpicture}
\caption{Read left to right: each step uses the previous step's result.}
\end{figure}
\end{frame}

\begin{frame}{From a Vague Request to a Concrete Task}
\small
A concrete prompt makes the intended result and the criteria for success explicit.
\par\smallskip
\courseexample{The weekly temperature-chart task}\par
\textbf{Vague prompt:} ``Make a chart from my data.''
\par\medskip
\textbf{Concrete prompt}
\begin{itemize}
\item \term{Input}: download the shared-drive \texttt{data.csv}, containing \texttt{date} and \texttt{temperature\_c}, into the working folder.
\item \term{Output}: create \texttt{plot\_temperature.py} and save a line chart to \texttt{results/temperature.png}, with dates in order and Celsius units.
\item \term{Constraints}: keep the input file unchanged and use the project Python environment.
\item \term{Checks}: run the script, compare plotted dates and values with the CSV, inspect the chart, and report the command used.
\end{itemize}
\par\smallskip
These details give the agent an observable target. The checked script can be reused when next week's CSV arrives.
\end{frame}

\begin{frame}{The Prompt Is Part of the Context}
\small
\setlength{\abovecaptionskip}{2pt}
\term{Context} is the input supplied to an LLM call, including more than the latest user message.
\par\smallskip
\courseexample{The chart exists; the user now says ``Fix the axis label.''}
\begin{figure}\centering
\begin{tikzpicture}
\node[agentNode,text width=3.1cm] (a) {\textbf{Current request}\\``Fix the axis label''};
\node[agentNode,text width=3.1cm,right=5mm of a] (b) {\textbf{Earlier instructions}\\Celsius;\\CSV unchanged};
\node[agentNode,text width=3.1cm,right=5mm of b] (c) {\textbf{Retrieved material}\\Script; chart; tool results};
\node[agentNode,text width=4cm,below=10mm of b] (m) {Input to the next LLM call};
\coordinate (join) at ([yshift=-5mm]b.south);
\draw[draw=SessionCharcoal,line width=.8pt] (a.south)|-(join);
\draw[draw=SessionCharcoal,line width=.8pt] (c.south)|-(join);
\draw[draw=SessionCharcoal,line width=.8pt] (b.south)--(join);
\draw[agentArrow] (join)--node[right,font=\scriptsize]{assembled by the harness}(m.north);
\end{tikzpicture}
\caption{Selected instructions and material accompany the new request.}
\end{figure}
\begin{itemize}
\item Tool definitions and selected conversation history may also be included.
\item The \term{context window} limits tokens per call; the full input may greatly exceed the new message.
\end{itemize}
\end{frame}

\begin{frame}{Reuse Instructions and Procedures}
\small
Recurring guidance can be stored once and loaded into context when it applies.
\begin{itemize}
\setlength{\itemsep}{2mm}
\item \term{Task prompt}: the current request.\\
\courseexample{Example:} ``Create this week's chart from the shared-drive CSV.''
\item \term{Project instructions}: standing rules for work in the project.\\
\courseexample{Example:} preserve input data, label units, and save figures in \texttt{results/}. Codex supports \texttt{AGENTS.md}; conventions vary by application.
\item \term{Skill}: a reusable procedure, with optional scripts and reference material.\\
\courseexample{Example:} a plotting skill describes how to read columns, choose axes, produce the chart, and check it. In the Agent Skills format, instructions live in \texttt{SKILL.md}.
\end{itemize}
\par\smallskip
Skill metadata helps the agent discover a relevant procedure; its instructions can then be loaded into context.
\par\smallskip
\textbf{Skills guide the procedure; tools perform its operations.} The plotting skill can guide the use of file tools and Python execution.
\end{frame}

\begin{frame}{Managing Limited Context}
\small
Conversation history and tool outputs accumulate as work continues. \term{Context engineering} determines which information accompanies the next LLM call.
\begin{itemize}
\setlength{\itemsep}{2mm}
\item \term{Retrieval}: load material relevant to the current step.\\
For an axis-label fix, retrieve the plotting code and current chart; a full execution log may add little.
\item \term{Compaction}: replace earlier conversation detail with a shorter summary.\\
For the chart task, preserve the input location, Celsius units, script path, completed checks, and remaining work. A summary can omit useful details.
\item \term{Saved notes}: retain decisions across sessions.\\
A note influences a later LLM call when the harness retrieves it into context.
\end{itemize}
\par\smallskip
\courseexample{A concise handoff}\par
``Shared-drive CSV downloaded. Script: \texttt{plot\_temperature.py}. Keep dates sorted and use Celsius. Script runs; next check plotted values against the CSV.''
\end{frame}

\begin{frame}{Context Caching Reuses Computation}
\small
\setlength{\abovecaptionskip}{0pt}
\term{Context caching} reuses computation for an unchanged beginning of the input---its \textbf{prefix}---when a compatible cache is available.
\begin{figure}\centering
\begin{tikzpicture}[x=1cm,y=1cm]
\node[anchor=east,font=\small] at (0,.7) {Previous call};
\node[anchor=east,font=\small] at (0,-.25) {Next call};
\foreach \y in {.7,-.25}{
 \node[agentNode,text width=2cm,minimum height=8mm] at (1.35,\y) {Instructions};
 \node[agentNode,text width=3cm,minimum height=8mm] at (4.25,\y) {History so far};
}
\node[agentNode,text width=2.8cm,minimum height=8mm,fill=white] at (7.55,-.25) {New messages\\reply + request};
\end{tikzpicture}
\caption{Unchanged prefix: reuse computation. New messages: process normally.}
\end{figure}
\begin{itemize}
\setlength{\itemsep}{0pt}
\item Cached input can reduce cost and processing time; eligibility, prices, and retention depend on the provider.
\item Changing the prefix can reduce reuse. Cached input still occupies context space; an expired cache requires recomputation.
\end{itemize}
\par
\textbf{Caching reuses computation; compaction changes the input.} A summary may shorten context but invalidate a cached prefix.
\end{frame}

\begin{frame}{Verify the Result}
\small
A script that runs successfully can still produce the wrong chart.
\par\medskip
\courseexample{Example check: three observations in the CSV}
\begin{center}
\begin{tabular}{ll}
\textbf{Date} & \textbf{Temperature (Celsius)} \\
2026-10-01 & 20 \\
2026-10-02 & 22 \\
2026-10-03 & 21 \\
\end{tabular}
\end{center}
\begin{itemize}
\item \textbf{Data agreement}: three points in date order, with a peak of 22 on October 2; axis labels show dates and Celsius.
\item \textbf{Input preservation}: the original CSV is unchanged.
\item \textbf{Reproducibility}: rerunning \texttt{python plot\_temperature.py} in the recorded environment regenerates the saved chart.
\item \textbf{Reusable work}: the checked script and its run instructions are saved in the Git project.
\end{itemize}
\end{frame}
