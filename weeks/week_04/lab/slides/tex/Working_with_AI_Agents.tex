\begin{frame}{LLM Families and Developers}
\small
A \term{large language model (LLM)} processes context and generates text, code, or requests to perform actions.
\begin{itemize}
\setlength{\itemsep}{3mm}
\item \href{https://developers.openai.com/api/docs/models}{\textbf{GPT family}} --- developed by \textbf{OpenAI}.\\
Examples: GPT-6 Astra, GPT-6.1 Sol, GPT-6 Luna.
\item \href{https://platform.claude.com/docs/en/models/overview}{\textbf{Claude family}} --- developed by \textbf{Anthropic}.\\
Examples: Claude Fable 5, Claude Opus 5.5, Claude Sonnet 5.5.
\item \href{https://ai.google.dev/gemini-api/docs/models}{\textbf{Gemini family}} --- developed by \textbf{Google DeepMind}.\\
Examples: Gemini 4 Argon, Gemini 3.8 Flash.
\item \href{https://docs.x.ai/developers/models}{\textbf{Grok family}} --- developed by \textbf{xAI}.\\
Examples: Grok 4.20, Grok 4.7.
\item \href{https://api-docs.deepseek.com/quick_start/pricing/}{\textbf{DeepSeek family}} --- developed by \textbf{DeepSeek}.\\
Examples: DeepSeek-V4-Pro, DeepSeek-V4.1-Flash.
\end{itemize}
\end{frame}

\begin{frame}{Agent Applications: LLM + Harness}
\small
An \term{agent harness} supplies information to the model and executes its requested actions through \term{tools}, such as file readers and command runners.
\[
\underbrace{\text{LLM}}_{\text{selects actions}}
+\underbrace{\text{harness}}_{\text{runs tools and manages context}}
=\text{AI agent}
\]
\begin{itemize}
\setlength{\itemsep}{2mm}
\item \href{https://developers.openai.com/blog/codex-as-a-platform}{\textbf{Codex}} (OpenAI): an agent for coding and project work.
\item \href{https://code.claude.com/docs/en/overview}{\textbf{Claude Code}} (Anthropic): an agent that reads files, edits code, and runs commands.
\item \href{https://cursor.com/docs/agent/overview}{\textbf{Cursor Agent}} (Cursor): an agent integrated into the code editor.
\item \href{https://geminicli.com/docs/}{\textbf{Gemini CLI}} (Google): an agent used through the terminal.
\item \href{https://docs.github.com/en/copilot/concepts/copilot-surfaces/copilot-on-github}{\textbf{GitHub Copilot}} (GitHub): agent features for repository tasks and code review.
\end{itemize}
\par\smallskip
An application may support several models. Choose the application and the model separately where supported.
\end{frame}

\begin{frame}{Specify the Task with a Prompt}
\small
A \term{task prompt} tells the agent what to do now. Give the input, desired output, constraints, and a way to check completion.
\par\medskip
\courseexample{Our task: a temperature chart}\par
The working folder contains \texttt{data.csv}, with columns \texttt{date} and \texttt{temperature\_c}.
\begin{quote}\small
Create \texttt{plot\_temperature.py} to plot daily temperature in date order. Label the axes Date and Temperature (Celsius), and save the chart to \texttt{results/temperature.png}.
\par\smallskip
Keep the input data unchanged. Use the project Python environment. Run the script, inspect the chart, and check the dates, values, and units. Report the files changed and the command used.
\end{quote}
\par\smallskip
This gives the agent an observable target: a runnable script and a checked chart.
\sourcehint{OpenAI, Prompt engineering}{https://developers.openai.com/api/docs/guides/prompt-engineering}
\end{frame}

\item A \term{CLI} accepts text commands, such as \texttt{python plot\_temperature.py}. The \term{terminal} hosts the session; the \term{shell} interprets commands.
\end{itemize}
\textbf{Use programs for repeatable rules; use the model for interpretation.} Once checked, the plotting script can run again on new data.

\end{frame}

\begin{frame}{The Prompt Is Part of the Context}
\small
\setlength{\abovecaptionskip}{2pt}
\term{Context} is the input the harness supplies to the model for its next response.
\begin{figure}\centering
\begin{tikzpicture}
\node[agentNode,text width=3.2cm] (a) {Instructions\\and task prompt};
\node[agentNode,text width=3.2cm,right=5mm of a] (b) {Tool definitions\\and retrieved files};
\node[agentNode,text width=3.2cm,right=5mm of b] (c) {Conversation\\and tool results};
\node[agentNode,text width=4cm,below=3mm of b] (m) {Input to the next model call};
\draw[agentArrow](a.south)--++(0,-.2)-|(m.north);
\draw[agentArrow](b)--(m);
\draw[agentArrow](c.south)--++(0,-.2)-|(m.north);
\end{tikzpicture}
\caption{The harness assembles the model input.}
\end{figure}
\begin{itemize}
\item A \term{token} is a unit of input or output. The \term{context window} limits how much a call can accommodate.
\item The harness loads relevant files and selects or summarizes earlier history.
\end{itemize}
\courseexample{``Fix the axis label''} can accompany the CSV, script, and history: a short message can have a large input.
\end{frame}

\begin{frame}{Keep the Working Context Relevant}
\small
\term{Context engineering} selects and maintains relevant information. Even a large context can contain details the model overlooks.
\begin{itemize}
\item \textbf{Load what helps.} For a plotting error, retrieve the relevant code and error message.
\item \textbf{Keep related work together.} Revise the chart in one session; start a new one for unrelated work.
\item \textbf{Preserve decisions.} \term{Compaction} replaces earlier detail with a shorter summary. Check that essential requirements survive.
\item \textbf{Separate lengthy side tasks.} A \term{subagent} can investigate in a separate context and return a concise result.
\end{itemize}
\par\smallskip
\courseexample{A handoff to a fresh session}\par
``The plotting script runs. Keep dates sorted and use Celsius. Next: compare the chart with \texttt{data.csv}.''
\par\smallskip
Saved notes or \term{memory} help later sessions only when retrieved into their context.
\sourcehint{CarpeDiem, Agent cost-saving tips (Part 1)}{https://www.bilibili.com/video/BV1fsbH6iEyq}
\end{frame}

\begin{frame}{Context Caching Reuses Computation}
\small
\setlength{\abovecaptionskip}{2pt}
\term{Context caching} reuses computation for an unchanged input prefix when a compatible cache is available.
\begin{figure}\centering
\begin{tikzpicture}[x=1cm,y=.6cm]
\node[anchor=east,font=\small] at(0,1){Previous call};
\node[anchor=east,font=\small] at(0,0){Next call};
\foreach \y in {0,1}{\node[agentNode,text width=2cm,minimum height=6mm] at(1.3,\y){A};}
\foreach \y in {0,1}{\node[agentNode,text width=2cm,minimum height=6mm] at(3.7,\y){B};}
\node[agentNode,text width=2cm,minimum height=6mm] at(6.1,0){C};
\end{tikzpicture}
\caption{Reuse A + B; process the new C.}
\end{figure}
\begin{itemize}
\item Eligible cached input can cost less to process. Retention and prices depend on the provider.
\item Changing earlier instructions or history can invalidate reuse. Cached text still occupies context space.
\item Cache expiry requires recomputation; compaction changes which information the model receives.
\end{itemize}
\textbf{Judge the completed task:} a high cache-hit rate alone does not imply low cost or good results.
\sourcehint{CarpeDiem, Agent cost-saving tips (Part 2)}{https://www.bilibili.com/video/BV1ZUek6uE54}
\end{frame}

\begin{frame}[fragile]{Reuse Instructions and Procedures}
\small
Keep recurring guidance in files the agent can load.
\par\smallskip
\begin{columns}[T]
\begin{column}{.48\textwidth}
\term{Project instructions}\par
Rules for work in this project. Codex uses \texttt{AGENTS.md}; filenames and scope vary across applications.
\par\smallskip
\courseexample{Chart project rules}
\begin{itemize}
\item Keep input data unchanged.
\item Include units on axes.
\item Save figures in \texttt{results/}.
\end{itemize}
\end{column}
\begin{column}{.48\textwidth}
A \term{skill}\par
A reusable procedure, with optional code and references. In the Agent Skills format:
\begin{verbatim}
plot-data/
  SKILL.md
  scripts/
  references/
\end{verbatim}
\courseexample{Plotting procedure:} read columns and units, create the figure, inspect it, and report checks.
\end{column}
\end{columns}
\par\smallskip
The agent discovers a skill by its name and description, then loads its instructions when relevant. The skill guides tool use.
\sourcehint{Agent Skills, Overview}{https://agentskills.io/home}
\end{frame}

\begin{frame}{Connect External Tools with MCP}
\small
Suppose the CSV is stored in a shared cloud folder. The agent needs an authorized way to retrieve it.
\par\smallskip
\term{Model Context Protocol (MCP)} standardizes how an AI application communicates with servers exposing tools and context.
\begin{figure}\centering
\begin{tikzpicture}
\node[agentNode,text width=3.1cm] (h) {Agent application\\with an MCP client};
\node[agentNode,right=9mm of h] (s) {MCP server};
\node[agentNode,right=9mm of s] (d) {Cloud drive};
\draw[agentArrow,<->] (h)--node[above,font=\scriptsize]{MCP}(s);
\draw[agentArrow,<->] (s)--(d);
\end{tikzpicture}
\caption{An external connection for the same chart task.}
\end{figure}
\begin{itemize}
\item A server can offer \textbf{tools} to act, \textbf{resources} to read, and \textbf{prompt templates} to reuse.
\item A drive tool could retrieve the CSV; the agent then uses its existing plotting workflow.
\item Local files can use the application's file tools directly. Add an MCP connection when a needed service provides one.
\end{itemize}
\sourcehint{Model Context Protocol, Architecture overview}{https://modelcontextprotocol.io/docs/learn/architecture}
\end{frame}

\begin{frame}{Verify the Work Before Reusing It}
\small
A successful tool call or a confident completion message is evidence to inspect; compare the actual result with the task.
\begin{enumerate}
\item \textbf{Inspect the changes.} Review the script and confirm the input file was preserved.
\item \textbf{Reproduce the run.} Record the command and Python environment; rerun the script.
\item \textbf{Check the output.} Compare dates and values with the CSV; inspect axis labels and units.
\item \textbf{Keep the checked version.} Commit the script with Git so it can be reused or revised.
\end{enumerate}
\par\medskip
\courseexample{For temperatures of 20, 22, and 21 Celsius,} the chart should preserve the date order and have its highest point at 22.
\par\medskip
A \term{sandbox} restricts execution; \term{approvals} authorize actions. Retrieved files may contain \term{prompt injection}: instructions that try to redirect the agent. Treat external content as data to assess.
\end{frame}

\begin{frame}[fragile]{Practice: Run, Check, and Reuse}
\small
Create a working folder and save this practice file as \texttt{data.csv}:
\begin{verbatim}
date,temperature_c
2026-10-01,20
2026-10-02,22
2026-10-03,21
\end{verbatim}
\begin{enumerate}
\item Choose an agent application and a supported model. Give it the chart prompt and access to this folder.
\item Follow one tool call: inspect what it reads or runs and the result returned to the model.
\item Review the script, rerun it, and check the chart against the CSV.
\item Add one observation to the practice CSV yourself; rerun the same script.
\end{enumerate}
\par\smallskip
\textbf{Extend the workflow:} save a project rule for axis units, or package the plotting procedure as a skill when supported.
\end{frame}
